By hand, on your Mac

These need your password, your keychain or a week of your time, so no pull request can do them.

  • Grant Full Disk Access to the installed v0.1.0 with the + button in System Settings → Privacy & Security → Full Disk Access.
  • Release v0.2.0: build the .dmg, tag it and publish it on GitHub. Signing happens only on your Mac.
  • The update test (#13): download v0.2.0 in a browser, install it over v0.1.0, and check that Full Disk Access is still on. Your Mac holds the signing certificate, so this proves it for your Mac only; a Mac without the certificate stays on the plan's still unverified list until a tester tries it.
  • The 7-day run: add Telescope to System Settings → General → Login Items, use it every day, and read each day's search times.
  • Back up the signing certificate as a .p12 file, kept somewhere other than this Mac.

How a new file reaches the results

Without this, Telescope only knows the files that existed when it started. Save a PDF a minute later and searching for it finds nothing, which is the first thing that would make you stop trusting it.

Think of a shop's price list. When a supplier rings the doorbell to say a shelf changed, the front desk checks whether it's a shelf the shop sells from. If it is, someone in the back room writes a fresh copy of the whole list while customers keep reading the old one, then swaps the new copy onto the counter in one move.

  • The doorbell. macOS keeps a running log of which folders changed, called FSEvents. macOS notices a change within about 10 ms, and Telescope asks it to bundle changes for about 0.2 s so a burst of saves arrives as one note. So the Swift side hears “~/Documents changed” about 0.2 s after you save there.
  • The front desk. Swift passes the folder to the Rust core through one new call in the hatch. A Rust function called in_scope answers one question: is this a folder Telescope lists? It uses the same skip rules as the scan, so a change inside ~/Library/Caches or node_modules is ignored and nothing else happens. If macOS says it dropped some notes, which can happen during a huge npm install, Telescope skips the question and rebuilds anyway.
  • The back room. If the answer is yes, Rust rebuilds the whole list on a background thread: about 0.15 s for about 48,000 entries. Searches keep using the old list meanwhile. Only one rebuild runs at a time, and at most one more waits behind it. While files keep changing, as during a long download, rebuilds start at least 0.5 s apart so Telescope doesn't spend all its time rebuilding; step 3 measures and tunes that gap.
  • The swap. The new list replaces the old one in a single step, and the old one is freed.
  • The counter. If the window is open, Swift runs your search again and keeps the same file selected. If it's hidden, Swift notes that the results are old and runs the search the next time you open it.

Rebuilding everything sounds wasteful, but 0.15 s of background work after a change is cheap, and it can't drift out of step with the disk. Editing just the changed folders in place comes in M3, together with the saved list.

Full Disk Access

macOS guards a few folders one by one: Desktop, Documents, Downloads, iCloud Drive, and cloud drives such as Dropbox. The first time an app reads one, macOS stops it and shows a pop-up asking whether to allow it. A search tool reads them in the background, so those pop-ups would appear at random moments, one per folder.

Think of an office building with locked rooms. You can hand out a key for each room as someone knocks, or give one master key at the front desk. Full Disk Access is the master key, and System Settings is the front desk. The part of macOS that keeps track of who holds which key is called TCC.

  • Checking for the key. At launch, Telescope tries to open a file that only the master key unlocks and that never triggers a pop-up: macOS's own list of permissions, opened read-only. If that works, it has Full Disk Access.
  • Without the key. Telescope skips the guarded folders, so no pop-up ever appears, and the window shows one line: it needs Full Disk Access, with an Open Settings button.
  • Quit & Reopen. After you switch Full Disk Access on, macOS offers to quit and reopen Telescope. An app only gets the new permission when it starts again, and on that start Telescope scans the folders it skipped.
  • Across updates. macOS remembers the key by the app's signing certificate, which stays the same in every release. A downloaded update still goes through Gatekeeper once (Open Anyway), and the update test (#13) checks that the key survives it on your Mac.

Moved to M3

Each of these is useful but not needed to use Telescope every day, and each has its own GitHub issue.

  • An “index everything” switch for the whole home folder, about 2.4 million entries instead of 48,000 (#21).
  • External drives, which come and go while Telescope runs (#22).
  • Per-folder updates and a bookmark in the FSEvents log (#23). Telescope saves its list and its place in the FSEvents log, so after a restart it reads only what changed while it was closed and edits just those folders, instead of rebuilding everything.
