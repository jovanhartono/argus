How Telescope opens instantly

Without a saved list, every launch reads every folder again before the first search can run: about 0.1-0.5 s for the default folders and 10 s for a whole home folder. On a Mac that restarts each morning, that is a pause you feel every day.

Think of a shop that keeps last night's price list instead of counting every shelf each morning. Next to the list it keeps a bookmark in the delivery log. In the morning it opens with the old list at once, then reads the log from the bookmark on and fixes only the shelves that changed overnight.

  • The price list. A background thread writes the list to ~/Library/Application Support/io.github.jovanhartono.telescope/index 2 s after it changes, into a new file that then replaces the old one in one step, so a crash mid-write never leaves half a list. 986 KB for 48,127 entries.
  • The bookmark. macOS's change log for folders, FSEvents, numbers every change. Telescope saves the number of the last change its list includes, and the log's own name. If the log was wiped since, after a disk repair say, the name differs and Telescope scans instead.
  • The morning. At launch the saved list answers searches at once. macOS replays the changes made while Telescope was closed, and each changed folder is read again and patched in: about 1 ms per change.

How a result earns its place

A launcher you trust puts the file you meant first. Spotlight often doesn't: it ranks by its own guesses and knows nothing of what you opened this morning. M3's ranking adds up a few plain points, like a judge's score card.

  • How well the name matches. Letters in order score; letters at the start of a word score more. This is M0's scoring, unchanged.
  • How deep the file sits. Each folder down costs a little, so ~/report.pdf beats a report.pdf buried in a backup.
  • Name before folder. When you type two words and one is only in a folder's name above, that word earns 4 points less than if it were in the file's own name. 4 is worth two folder levels.
  • Apps. An app pays no depth cost, so it wins a tie with a file of the same name, but a weaker app match never beats a better file match.
  • What you open. Each open adds to a path's frecency score, which halves every 30 days. The boost is at most four letters' worth, so it lifts a good match over an equal one but can't drag a poor match to the top.

The golden set checks it: 20 of 20 searches put the expected file in the top 3, on the default folders and on the whole home folder, every one at rank 1. The list itself stays on your Mac.

Decisions

Taken on 27-28 Oct 2026 while the steps were built, each measured where a number could settle it. Every one is open to change.

What remains

  • The index everything switch (#21): the switch is in the health view and works without a relaunch, but with it on ~/Library changes every few seconds, and each change patches a copy of the 2.5-million-entry list. Memory settles at 80 MB and peaked at 152 MB, against 60 and 150 MB, and the patches cost about 3% of one core. Patching without a second copy (#42) should bring both down.
  • External drives in the window (#22): the app has to tell the core when a drive is plugged in or ejected. A writable disk image you made yourself is still listed, and Time Machine on APFS may be missed.
  • Damaged saved lists with drives (#55): random damage tests that cover drives and removed entries.
  • Restart under 300 ms on a quiet Mac: every launch timing so far ran at load average 11-18.
  • Hand checks with the screen unlocked: the details pane, the folder label, app rows and the health window in light and dark; VoiceOver reading “Search in notes”; Return on an app; the first macOS question about controlling Finder.
