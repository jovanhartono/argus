Bottom line

  • Worth building as your daily driver and as open source. Raycast 2 and Wox 2.4 already keep their own file lists on both systems, so Telescope's edge is weight: no hidden web browser inside, a target of under 60 MB of memory while idle, and a goal of running well on a 4 GB PC (not yet tested beyond your Mac).
  • Speed is mostly solved. Fuzzy matching every name in your home folder took 6-12 ms per keystroke on your Mac.
  • The hard parts are putting the right file first, keeping up with file changes, making the window feel like Spotlight, and Windows.
  • Rust does all the searching. A thin Swift window shows the results on macOS. Windows gets its own thin window at milestone 5 (M5).
  • No database. The list of file names is Telescope's own file, read straight from disk.
  • Shipping is free: a .dmg on GitHub. Because we never pay Apple's $99 a year, each user approves the app once in System Settings (still to confirm on macOS 15.1).
  • Spotlight is not a reliable backup. On your Mac it found 16 of the 141 files named "telescope".
  • The biggest risk is the project stalling. Three Rust launchers, Loungy, Gauntlet and Kunkun, went quiet. Every milestone has a time limit.

How it works, in plain words

Eight ideas carry the whole design.

1A kitchen and a waiter

Rust is great at fast searching and awkward at drawing Mac windows. Swift is the opposite.

Picture a restaurant. The waiter takes your order and brings the plate; the kitchen cooks. They talk only through a small hatch, using a fixed set of order slips.

The waiter is a thin Swift window. The kitchen is the Rust core, where every search happens. The hatch is about 10 Rust functions written in C style, the one format both sides understand; you write no C yourself. At M5, Windows gets its own waiter and reuses the same kitchen.

2A phone book of file names

Asking the disk "which files match tel?" means opening every one of the 266,968 folders in your home folder. That took 10.7 s on your Mac.

A phone book solves this: write every name down once, then look names up in the book instead of knocking on every door.

The book is called the index. By default it skips clutter like ~/Library (but keeps iCloud Drive and other cloud drives), hidden folders, tool downloads and caches like node_modules, and the thousands of pieces inside packages like Photos Library, which Finder shows as one file. On your Mac on 27 Oct 2026 that left 47,933 entries, indexed in 0.15 s. An "index everything" switch covers all 2.44 million that day; the whole home folder's count changes from day to day (see Measured on your Mac). Your own list in ~/.config/telescope/ignore can skip more folders, or bring back one Telescope skips, like ~/.config.

3Writing each folder once

Storing every file's full path repeats "/Users/you/Documents/" for every file inside that folder. For your Mac that adds up to 491 MB.

An address book can say "same street as #3" instead of writing the street out again.

Telescope stores each entry's own name plus the number of the folder it sits in. The names alone take 66 MB for your whole home folder and about 14 MB (estimate) for the 353k default-folder entries of 25 Oct 2026. With the stricter rules of 27 Oct 2026, the whole index for 47,933 entries measured about 1.2 MB. Full paths are rebuilt only for the 50 rows on screen.

4Reading the index without loading it

Loading the whole index file into memory at every launch is slow, and the app keeps holding that memory while the window is hidden.

Compare photocopying a whole reference book with reading it on the library shelf. On the shelf you touch only the pages you need, and the librarian can put pages away when space runs short.

Programmers call this memory-mapping. macOS loads pages of the index file only when a search touches them, and can drop them while you are not searching.

Measured later, on 28 Oct 2026: every search reads every list in the index, so after the first search the whole file is in memory anyway. Reading all of it at launch took about 20 ms for your whole home folder, so Telescope reads it in one go. See "Saving the index" below.

5What happens when you type

Every keystroke has to check up to 2.36 million entries (your whole home folder on 25 Oct 2026) within a few milliseconds.

Think of sorting job applications: a quick scan throws out every CV missing a required skill, and only the rest get read carefully.

The quick scan is a letter fingerprint: 8 bytes per name recording which letters it contains, so any name missing a typed letter is skipped. The careful read is fuzzy matching. Your 2.36 million entries share only 1.02 million different names, because names like README.md repeat across folders, so each name is matched once. Results are then ranked by match quality, by frecency, and by how deep the file sits.

6Throwing away old searches

Typing "tel plan" starts 8 searches in under a second. Finishing all 8 wastes CPU on searches you no longer want.

Give each search a ticket number. The kitchen abandons any order whose ticket is no longer the newest, and the waiter throws away any plate with an old ticket.

The searchers are threads: workers that share one app's memory, one per CPU core minus one, so the window always has a core free. In a test with a single searcher, 8 fast keystrokes delivered 1 result; the full set of searchers is tested at M1.

7Keeping up with new files

Files change all day, and rescanning everything at each launch takes seconds.

macOS keeps a numbered logbook noting which folders changed. Telescope bookmarks the last entry it read; after a restart it reads only the new entries and re-checks just those folders.

The logbook is called FSEvents. On your Mac, catching up on a short gap after a restart took 8 ms, and macOS reported new files 4-12 ms after they were created.

8Why macOS keeps Telescope's permissions

Telescope needs Full Disk Access to see some folders. If macOS forgot that after every update, you would grant it again each time.

macOS recognises apps the way a building guard recognises ID cards. By default every build gets a throwaway card that changes each time, so the guard forgets you. One homemade card that never changes keeps you recognised.

The card is a code-signing certificate; the throwaway kind is called an ad-hoc signature. The certificate comes with a secret key used to stamp each build, and whoever holds the key can stamp builds that look like yours. Telescope uses one self-signed certificate, valid for 10 years, with the key kept on your Mac. Rebuilds on the same Mac keep their permissions; a downloaded update is tested on your Mac at M2, and another Mac needs a tester.

The window

  • Built once at launch, then only shown and hidden.
  • Telescope never takes over as the active app, so the app you came from gets focus back when the window closes.
  • Opens on the current Space and over full-screen apps.
  • Japanese and Chinese typing work: no search runs while the IME is still composing a word.
  • Settings and the index health view use SwiftUI, which is fine for windows opened rarely.

Keys

  • Cmd+Shift+Space shows or hides it; you can change it.
  • Enter opens; Cmd+Enter shows it in Finder.
  • Tab searches inside the selected folder.
  • Option+Cmd+C copies the path, as in Finder; Cmd+I opens the details pane.
  • Cmd+Y opens Quick Look. Space was dropped on 27 Oct 2026: an empty search box has no results to preview.
  • Search in the current Finder folder has no default key and asks for Finder access the first time you use it.

Keeping the hatch safe

  • JavaScript cleans up memory for you; at the hatch, nobody does. If Swift kept a pointer to Rust's results after Rust freed them, it would read garbage or crash. So Swift copies the 50 rows, and Rust frees its own copy right away.
  • Every Rust function at the hatch catches panics and returns an error code, so a Rust bug shows an error instead of closing the app.
  • The app checks at launch that Swift and Rust agree on the hatch version, and CI fails if they drift apart.
  • All the risky pointer code on the Swift side sits in one file.

Build and ship

  • One script builds the Rust core for Apple Silicon and Intel and merges them into one compiled file. Xcode, Apple's app builder, packs it into the app, much like a bundler pulls in a dependency.
  • Runs on macOS 13 or later.
  • One app for both chip types, in a .dmg on GitHub Releases, plus a one-command build from source.
  • Signed with the 10-year self-signed certificate on your Mac, never on CI machines.
  • Without Apple's $99 a year ID the app is not notarized, so Gatekeeper stops the first launch. Each user opens the app, then System Settings, Privacy & Security, Open Anyway. Control-click no longer skips this since macOS 15.
  • The optional update check only links to the new .dmg; nothing installs itself.
